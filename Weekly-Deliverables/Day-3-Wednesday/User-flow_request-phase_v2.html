Vello · User flow · Request phase

Post a request for weekday walks and get the first replies

Sam needs a walker for Loki every weekday. The flow runs from tapping + to seeing the first replies, where the Compare phase starts. Inside the app only, in three stages: Post, Wait and Come back.

Assumptions to verify

Product rules the flow depends on that the prototype doesn't have yet. Each number matches a tag in the flow.

#AssumptionPrototype today
1The "No dog walkers nearby yet" button on Home opens the request form.The button says "See your open request" and opens the existing request.
2A second open dog-walking request shows a warning, and both requests stay open.A new post replaces the old request and its replies without warning.
3Leaving a form with any field filled asks Sam to confirm the discard.Cancel discards everything without asking.
4Addresses outside Vello's area are blocked and offered a waitlist.Any address is accepted.
5If the connection drops, posting pauses, the draft is kept, and a request is never posted twice.No offline or failure state is designed.
6Only verified dog walkers whose area covers the address get the request, and Sam is told when there are none.Always shows "Request posted to your block".
7Sam can edit or close an open request, and walkers who replied are told about either change.Editing isn't wired up, and closing only happens on the device.
8After 24 hours with no replies, Sam gets a push and a prompt to widen the time or budget.The empty state promises "We'll let you know the moment someone does", and nothing else happens.
9A request with no replies expires after 7 days and can be posted again pre-filled.Requests never expire.
10Each reply sends a push that opens the request. With notifications off, only the Home card updates.The Home bell always says "No new notifications", and the Profile switch changes nothing.
11A walker removed by a Community Admin after replying shows "No longer available on Vello", with Book off.Not covered.
